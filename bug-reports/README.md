# Bug Reports

This folder contains defect documentation written to be actionable by a developer without further back-and-forth.

Each report follows a fixed structure:

* Finding title and ID (e.g. `BUG-01`, `SEC-01`)
* Location / route and environment
* Reproducibility (Always / Intermittent / Unknown)
* Steps to reproduce
* Expected result vs. actual result
* Severity (impact) and Priority (urgency), tracked as separate fields
* Root-cause hypothesis, clearly labeled as a hypothesis unless confirmed
* Recommended fix

Severity and priority are not always aligned in these examples on purpose — a cosmetic issue on a high-visibility screen can outrank a rare but low-impact functional bug, and the reports reflect that distinction rather than collapsing it.

Confidential company information and proprietary materials are excluded; sanitized or recreated evidence stands in for real screenshots and tickets.
