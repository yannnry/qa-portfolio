# QA Case Studies

This folder contains full case studies that walk through a testing effort end to end: objective, scope, test design, execution, findings, and verification. Each one is structured close to how a real audit report is compiled, so it shows reasoning, not just output.

A case study typically includes:

* **Objective** — what was being validated and why
* **Scope** — screens, routes, or flows covered
* **Test design** — scenarios, boundary conditions, positive/negative cases, exploratory notes
* **Execution** — environment, browser/device, build or version
* **Findings** — normalized by type (Bug, Security Risk, Performance, Accessibility, UX Improvement, Positive Finding), with severity and priority
* **Verification** — whether the fix was confirmed and regression was performed

Planned case studies:

* Authentication and Account Testing
* 50-Question Free Trial Testing
* Question Bank Testing
* Security Testing (CSRF token gap, deadline-bypass verification)
* Regression and Release Testing

Confidential company information, internal documentation, and private testing evidence are excluded or recreated against a comparable application; the testing logic and findings are real.
